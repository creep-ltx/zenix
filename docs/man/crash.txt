CRASH(1)			Zenix manual

NAME
    crash - test that a crash is contained

SYNOPSIS
    crash
    crash stack
    crash kstack | idle
    crash sleep N | poke | damage | literal
    crash victim N [FILE] | read ADDR | write ADDR

DESCRIPTION
    Without an argument, executes an illegal instruction. The kernel must
    report "pid N (crash) killed: vector 4 ..." and kill only this program;
    the rest of the system keeps running.

    crash stack recurses, with a system call on every level, until its
    stack runs past its bottom. The stack guard must report
    "pid N (crash) overflowed its user stack: killed" and the system must
    go on.

    crash kstack and crash idle only do something in a kernel built for
    the test (make DIAG=-DSTACK_TEST, tools/diag-test.sh stack): they damage
    the guard of crash's own kernel stack (the process is killed with
    "overflowed its kernel stack") or of the idle process's (a kernel
    panic). In a normal kernel they say "still here" and exit with 1.

    The last four are for the shared-code tests (tools/pure-test.sh runs
    a build of crash with shared code, /tests/crashpure): crash sleep N
    sleeps N seconds and exits 0 (another process running the same code);
    crash poke changes a byte of its own constants and exits 0 (in the
    shared build: the code every process of it runs; the next start must
    find the damage); crash damage does the same and then faults (the
    kernel must say the shared code is damaged and name the processes
    still running it); crash literal opens, writes, reads into and
    spawns with string literals and prints what each system call said (a
    read into a literal must fail with -14 in the shared build). With
    memory protection on (DESIGN D41) a poke or a damage of the shared
    build ends the program at its write instead.

    The last three are for the memory protection tests (tools/mmu-test.sh):
    crash victim N fills a region of 8 KB with a pattern, says its
    address ("crash: victim pid P region ADDR"), sleeps N seconds (or
    until FILE exists) and says
    whether the pattern is "intact" (exit 0) or "damaged" (exit 1);
    crash read ADDR reads a long at ADDR (decimal, or hex with 0x) and
    prints it; crash write ADDR writes one there. With protection on, an
    address that is not crash's own memory ends it with the kernel's
    "memory protection:" line and status 139. Without protection a read
    goes through, and crash write refuses (exit 2) unless the kernel's log
    says protection is on: the write would land.

    A test program.
