DISKD(8)			Zenix manual

NAME
    diskd - the disk server

SYNOPSIS
    built into the kernel image; not run by hand. boot(8) registers it as
    the service "disk": the first call starts it, and a call after it
    ended (a crash, or a kill by root) starts it again (DESIGN D11)

DESCRIPTION
    Owns the disk hardware through privileged system calls (an IDE drive, or
    the SD card of a Raspberry Pi 4 / CM4 under Emu68) and offers the port
    "disk". It reads the partition table - an Amiga RDB at the start of the
    disk, else a PC table (MBR) - and serves named devices: ide0 (the whole
    disk, whatever the hardware), ide0p1, ide0p2 ... (partitions, numbered in
    the order found), ram0 (the RAM disk loaded by the bootblock, when
    there is one) and df0-df3 (floppy drives, 1760 sectors; df0 is looked
    for at start, df1-df3 on first use; no partitions). Access through a
    partition is limited to that partition.
    A handle is the device's slot. A slot keeps its device across rescans
    (the same sectors of the same medium; a partition renumbered by a change
    before it keeps its slot under its new name), so a filesystem server's
    handle never moves to another partition; a mounted device that vanished
    from the table keeps its slot until it is unmounted.
    Devices that share sectors overlap: the whole disk overlaps every
    partition, a type 0x76 partition the RDB partitions inside it, and two
    partitions of a damaged table may overlap. A device can be mounted by
    one filesystem server; mounting it, or opening it raw (fdisk, mkfs.ext2,
    fsck.ext2), is refused (-EBUSY, 16) while an overlapping device is
    mounted, and a write that touches a device another process has mounted
    is refused. A plain open may read anything. When the server that
    mounted a device has died, its mount is released the next time it is in
    the way. Besides read, write and info it offers DISK_FLUSH (make
    everything written so far durable: ATA FLUSH CACHE on IDE, SYNCHRONIZE
    CACHE on the A3000's SCSI disk; the SD driver waits for each write) and
    each device reports capabilities (flush works, flash or rotating,
    largest transfer). The flush capability is real: diskd tries a flush
    at start, and a drive that refuses it gets none (a line says so);
    DISK_FLUSH on such a device answers -EOPNOTSUPP (95). Floppies write
    synchronously with verify and count as flushable; the RAM disk as RAM.
    Only root may use it (the filesystem servers run as root): from any
    other user every request but DISK_LIST and DISK_INFO is answered
    -EACCES (13), because raw sectors would bypass every file permission.
    The port name "disk" is reserved for root.
    Protocol: kernel/diskproto.h.

PARTITION TABLES
    RDB: the partitions of the table, with their labels and types, placed
    by each partition's own geometry (DosEnvec Surfaces, BlocksPerTrack and
    SizeBlock), whatever tool wrote it. A partition whose geometry cannot be
    placed, or that does not fit the disk, is not served (a line says so).
    A partition chain that loops ends at the first block seen twice.
    MBR (sector 0 ends in 55 AA and holds plausible primary entries): each
    entry is a device; type 0x83 (Linux) is taken as ext2; type 0x76 holds an
    Amiga RDB of its own, whose partitions are listed after it (Emu68's way of
    putting Amiga partitions on a PC-partitioned card); every other type (FAT
    boot partitions, ...) is listed as "other" and never mounted. Extended
    partitions and GPT are not read.

NOTES
    Not done: extended partitions, GPT.
    Errors are negative errno numbers (kernel/errno.h): an unknown device
    -ENODEV, a bad handle -EBADF, a range outside the device -EINVAL, an
    overlapping mount -EBUSY.
