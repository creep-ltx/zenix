DISKD(8)			Zenix manual

NAME
    diskd - the disk server

SYNOPSIS
    built into the kernel image; not run by hand

DESCRIPTION
    Owns the disk hardware through privileged system calls (an IDE drive, or
    the SD card of a Raspberry Pi 4 / CM4 under Emu68) and offers the port
    "disk". It reads the partition table - an Amiga RDB at the start of the
    disk, else a PC table (MBR) - and serves named devices: ide0 (the whole
    disk, whatever the hardware), ide0p1, ide0p2 ... (partitions, numbered in
    the order found) and ram0 (the RAM disk loaded by the bootblock, when
    there is one). Access through a partition is limited to that partition.
    A device can be
    mounted by one filesystem server, which is then its only writer; tools
    such as fdisk, mkfs.ext2 and fsck.ext2 open devices raw, which is refused
    while mounted. Protocol: kernel/diskproto.h.

PARTITION TABLES
    RDB: the partitions of the table, with their labels and types.
    MBR (sector 0 ends in 55 AA and holds plausible primary entries): each
    entry is a device; type 0x83 (Linux) is taken as ext2; type 0x76 holds an
    Amiga RDB of its own, whose partitions are listed after it (Emu68's way of
    putting Amiga partitions on a PC-partitioned card); every other type (FAT
    boot partitions, ...) is listed as "other" and never mounted. Extended
    partitions and GPT are not read.

NOTES
    Not done: extended partitions, GPT.
