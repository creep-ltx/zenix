INIT(8)			Zenix manual

NAME
    init - mount the filesystems, keep logins and daemons running

SYNOPSIS
    started by boot; not run by hand

DESCRIPTION
    /bin/init is started by boot(8) on console 1. It first sets the
    console's colours from /etc/console (below), then prints /etc/motd, runs
    "mount -a" if there is an /etc/fstab (so the filesystems listed there
    are mounted before anyone can log in), starts "ifup -a" without
    waiting for it if /etc/network/interfaces has an "auto" line (the
    network, ifconfig(8): no login waits for a cable), and then looks
    after the ten
    virtual consoles (/dev/tty1 .. /dev/tty10, Amiga+F1 .. Amiga+F10), like
    a Unix init with a getty on each terminal:

    - console 1 gets a login(1) at once;
    - another console gets one the first time it is shown with nobody on
      it (the kernel tells init, as Linux's autovt does), so an unused
      console costs no memory;
    - a login that lets a user in (login --init) starts the user's shell
      and hands it to init, then ends: init now waits for the shell
      itself, so a session keeps no login in memory;
    - when a session ends (the shell ended: the user logged out), init
      prints "init: session ended, starting another" on that console and
      starts a new login there after half a second; a login that gives up
      (five wrong tries) is started again the same way.

    Each login runs with its console as standard input, output and error,
    which makes that console its controlling tty and its shell's.

DAEMONS
    Servers nobody calls (network listeners such as wasabid(8)) are kept
    running by init (DESIGN D24 7). /etc/daemons lists them, one a line,
    as /etc/svctab does (# starts a comment):

        NAME  NICE  PROGRAM [ARGUMENTS]
        wasabid 0   /sbin/wasabid --init

    The program is an absolute path, its text at most 79 characters and
    6 words; at most 4 lines are used (more are logged and ignored). The
    file must be root's and writable by nobody else, else init ignores it
    (said on console 1). init starts every line after "ifup -a" (waiting
    for neither), as root at that nice, standard input /dev/null, output
    and errors /dev/kmsg: everything it says goes to the kernel log
    (dmesg), never to a console. When one ends, init starts it again with
    the service manager's numbers (DESIGN D11): an end with status 0 is a
    stop (not started again until the next boot; root may start it by
    hand); any other end is counted, and the next start waits 0, 1, 2 or
    4 seconds after the first, second, third or fourth end within a
    minute; the fifth gives it up until the next boot. Status 75 is init's
    own "start me again at once": no wait, and counted only when the
    program ran less than 5 seconds (a quick restart loop is still given
    up). A program that cannot be started counts as an end. The kernel
    log says each step:

        init: wasabid: started /sbin/wasabid --init (pid 12)
        init: wasabid: /sbin/wasabid (pid 12) ended, status 75 (start
            me again)
        init: wasabid: /sbin/wasabid (pid 12) stopped (status 0): not
            started again until the next boot
        init: wasabid: given up after 5 ends in 60 s (the next boot
            starts it again)

    /etc/daemons ships with every line commented out: nothing runs until
    root removes a #.

THE CONSOLE'S COLOURS
    /etc/console holds the text console's settings, one per line (# starts
    a comment). Today there is one:

    colours N   2, 4, 8 or 16 colours ("colors" is the same; "auto", or no
                line, lets the machine decide: 16 with fast RAM on an AGA
                Amiga, 8 with fast RAM on OCS/ECS and on any machine with
                2 MB of chip RAM and no fast RAM, 2 below that).

    Fewer colours leave more chip RAM free: the screen takes 40, 80, 120 or
    160 KB for 2, 4, 8 or 16 colours, and on a machine without fast RAM
    the display also takes less of the chip bus the processor runs from.
    With 4 colours the console shows black, red, cyan and grey (red stands
    for red, yellow and magenta, cyan for green, blue and cyan); with 8 a
    bright colour is shown bold; with 2, grey on black. init reads the file
    once when it starts, so a change counts from the next boot (as
    Workbench's ScreenMode preferences). A value it cannot use is said on
    console 1: "init: /etc/console: colours 7: 2, 4, 8 or 16 (or auto)";
    16 on an OCS or ECS Amiga gives 8; without the chip RAM for the new
    screen the console stays as it was and init says so. The kernel says
    the new depth in its log (dmesg): "display: AGA chips, 2 bitplanes ...".

NOTES
    init waits for both kinds of event in one call (wait with the
    console flag, root only); a daemon's delayed start is an alarm that
    ends that wait. If /bin/login cannot be started (no memory
    left, for instance), init says so on that console and on its own
    output: "init: cannot start /bin/login: out of memory". On console 1
    it tries again every 5 seconds; another console gets a new try the
    next time it is shown.

FILES
    /etc/console, /etc/motd, /etc/fstab, /etc/daemons
