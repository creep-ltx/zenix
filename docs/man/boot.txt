BOOT(8)			Zenix manual

NAME
    boot - start the servers and init

SYNOPSIS
    built into the kernel image; not run by hand

DESCRIPTION
    The one process the kernel starts itself (pid 1). It registers the
    disk server and the root filesystem server as services (DESIGN D11:
    the first call to a service starts its server, and a server that
    died is started again by the next call):
      disk  ->  @diskd, nice -10. boot's first question to it (the list
                of devices) starts diskd.
      fs    ->  @fsd DEVICE fs -root -id ID, or @zfsd ... for ZenixFS,
                nice -10. The root DEVICE: the RAM disk from the boot
                floppy, else the partition of type ext2 or zenixfs marked
                bootable (fdisk boot), else the first such partition, else
                the bare disk. boot reads its superblock to choose the
                server; ID is the volume's place (start and size, in hex)
                and its uuid: at every start, the first too, the server
                looks for its volume by place, the uuid confirming it
                (user/volid.h, the same code mount(8) uses for the
                filesystems it mounts). Asking for the root inode starts
                it.
    Then it runs /sbin/zup (zup(8)) and waits for it: zup installs the
    root half of an update zenixboot left in memory, finishes or rolls
    back what a power cut left, or puts the previous version back; with
    nothing to do it ends at once. A zup still working after a minute
    is reported ("boot: /sbin/zup is still working (an update)") and one
    still working after 20 minutes is stopped (the next start finishes
    its work). "zup" means every process of that name: the new zup an
    update installs first runs the rest as a second process, which also
    outlives a first zup that crashed; boot waits for, and stops, both.
    Only when no zup runs any more does boot give the update bundle's
    memory back (SYS_update RELEASE), whatever zup did (if one cannot be
    stopped, the memory stays reserved and boot says so). With no
    /sbin/zup, boot says so only when an update is waiting. With an
    update waiting, a missing /sbin/zup or one that crashed, was stopped
    or failed leaves the update note "failed" for the bundle's version,
    so zenixboot(8) does not retire the bundle. boot's stack is 4 KB (it
    needs under 500 bytes): it stays in memory for ever.
    Then it registers the services listed in /etc/svctab (below) and
    starts /bin/init on console 1 and waits for it. Should init
    ever end, boot says so ("boot: /bin/init ended (status N), starting it
    again") and starts it again a second later. It exists because the idle
    process cannot wait for messages.

FILES
    /etc/svctab   services whose programs live on the disk, one a line:
                    PORT  NICE  PROGRAM [ARGUMENTS]
                  for example "ping 0 /bin/pingd". PROGRAM is an absolute
                  path (read as root when the service starts) or a
                  built-in image (@diskd, @fsd, @zfsd); at most 6 words in
                  80 bytes; NICE -20..19. Lines starting with # and empty
                  lines are skipped. Nothing is started at boot: the first
                  call to PORT starts the program, and the next call after
                  it ended starts it again (a server that ends with status
                  0 while idle has simply stopped). There is no start-at-
                  boot, restart or dependency field: a server that needs
                  another one calls it, and that starts it. A line that is
                  not of this form, or that the kernel refuses (a name a
                  port already has, more than 12 services), is reported
                  ("boot: /etc/svctab: line skipped: PORT") and skipped.
                  The file is read once, at boot: a change takes effect at
                  the next boot.

NOTES
    The two servers are essential: if diskd or the root server ends before
    it ever served, the kernel stops with "svc: an essential server ended
    before it served" (no disk, or no root filesystem); the server's own
    line before it says why. Every start and end is in the kernel log
    (dmesg, "svc:" lines).
