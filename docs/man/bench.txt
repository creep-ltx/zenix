BENCH(1)			Zenix manual

NAME
    bench - measure how fast Zenix is

SYNOPSIS
    bench
    bench dir [-q] DIRECTORY

DESCRIPTION
    Times a set of operations with the CIA E-clock (709,379 Hz on PAL, far
    finer than the 100 Hz tick) and prints microseconds per operation:
    a null system call, a malloc and free of small blocks (12 to 200
    bytes, in turn) and of blocks of 300 to 3,800 bytes, stat through the
    filesystem server, a message round
    trip, cached and uncached file reads, creating and deleting 50 small
    files, listing /bin, and printing 300 lines to the terminal (/dev/tty)
    twice: with the serial copy of the console off (only root may switch it
    off; for others that line says so) and on. With the copy on, the screen
    waits for the 115200-baud serial port only if the port has received
    something since boot (a terminal is attached); otherwise the copy drops
    what does not fit and the two lines are close. It is a development tool
    and is not meant for everyday use.

    Every open, read, write, close, mkdir, unlink and stat is checked: when
    calls fail, the line says "FAILED", how many and the first error, and
    gives no timing (a failed call is fast, so its time would mislead). The
    create and delete lines need a writable /tmp; their files are written
    through to the disk before each call returns (no write-back cache), so
    on a real disk they take milliseconds, not microseconds.

    bench dir DIRECTORY reads the directory both ways (DESIGN D49): one
    record a call (readdir) and in batches (readdirs, through libz), and
    checks that both give the same names, inodes and order, that every
    stat a batch gave is what lstat answers, and the call's own refusals
    (a buffer under 104 bytes or not 4-aligned). It prints the times of
    both, of an lstat of every name, the null call, a trip to the
    directory's server (fstat), a plain message trip (msgpingd), and an
    lstat of the first and the last name; then "bench dir: identical, N
    records, S stats" and status 0, or "bench dir: BAD" lines and status
    1. -q: only the checks.

    Numbers taken in an emulator are NOT hardware numbers. Run it on the real
    Amiga and write the result down with the date.

SEE ALSO
    msgping(1), uptime(1)
