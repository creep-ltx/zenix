MOUNT(8)			Zenix manual

NAME
    mount - list mounted filesystems, or mount one

SYNOPSIS
    mount
    mount [-t type] device dir
    mount [-t nfs] [-o options] host:/export dir
    mount -a

DESCRIPTION
    Without arguments, lists the mounted filesystems: device, mount point,
    type, size and free space in KB. The first line is the root filesystem.

    With a device and a directory, puts the device's filesystem on the
    directory. The directory must exist; what was in it is hidden until the
    unmount. Devices are the names the disk server gives: ide0p1, ide0p2
    ..., df0, df1 (see fdisk). Filesystems can be mounted inside each other
    (/mnt, then /mnt/sub).

    The type is ext2 or zenixfs. Without -t it is read from the partition's
    type in the partition table (fdisk add ... ext2|zenixfs).

    The filesystem's server is a service (DESIGN D11): mount reads the
    device's volume id (where it is and its superblock's uuid) and
    registers the service fs.DEVICE with the server for the type, at
    priority -10: for ext2 fsd, built into the kernel (the program that
    serves the root); for ZenixFS the file /sbin/zfsd (DESIGN D19), read
    from the root when it starts. The kernel's first call to it starts
    the server; should it crash or be killed, the next use of the
    filesystem starts it again (fsd from the kernel, no disk read; zfsd
    from /sbin/zfsd again), and it finds its volume by the id (a floppy
    without a uuid is then refused: it may have been swapped; mount it
    again). The servers' own messages and the service lines are in
    dmesg(1).

    ext2: a volume with an INCOMPAT feature other than filetype (ext4:
    extents, 64bit, flex_bg, ...) is refused and the features are named;
    one with an ext3 journal, an unknown read-only feature or the "has
    errors" state is mounted read-only with a line saying why (every write
    fails, EROFS). Details: docs/architecture.md section 10. A volume that
    was not unmounted cleanly (a power cut while it was written) is
    checked first by mount -a: "mount: DEV was not unmounted cleanly:
    fsck.ext2 -y DEV", then fsck.ext2's lines; one fsck.ext2 cannot
    repair is mounted as it is and stays marked. A plain mount only warns
    (umount it, then run fsck.ext2 -y). DESIGN D17.
    ZenixFS: changes are kept in memory and committed atomically three
    seconds after the first change, at sync(1) and at umount, so a power
    cut leaves the volume as it was at the last commit (docs/zenixfs.md).

    NFS (DESIGN D23): mount -t nfs nas:/volume1/zenix /nas puts a
    directory that a NAS or a Linux PC exports on dir (NFSv3 over TCP;
    -t nfs may be left out when the source has the form host:/export).
    The host is a name (/etc/hosts, then DNS) or an address, looked up
    again at every connection. Its server is /sbin/nfscd, one for each
    NFS mount, registered as the service fs.nfs0 .. fs.nfs7 (mount takes
    the first free one; the list shows that name and the type nfs; the
    source is in nfscd's first line in dmesg). A hand mount reaches the
    NAS before it answers, so a typo or a firewall is said at once
    ("the NAS did not answer", "the NAS refused the mount (its export
    rules)", "the NAS has no such export"; the details are nfscd's lines
    in dmesg). Options (-o, comma-separated, as on Linux):
      hard       the default: a request is tried until the NAS answers;
                 programs wait while it is off. Ctrl-C ends a program
                 waiting there (one that catches Ctrl-C, as the editor
                 does: kill -9). dmesg says "the NAS is not answering,
                 still trying" and later "the NAS answers again".
      soft       a request fails with an I/O error after the retries
                 (programs that do not expect errors may lose data).
      timeo=S    seconds without an answer before a retry (default 30).
      retrans=N  the retries of a soft mount (default 3).
      ro         read-only.
      sync       each write is on the NAS's disk when it returns.
      actimeo=S  file and directory attributes are trusted for S
                 seconds (0: asked every time; default 3-60).
      rw, defaults, async: accepted, the defaults.
    While the NAS does not answer, mount's list, df and sync never wait
    (the last known sizes; sync tells of unsaved data in dmesg).
    An NFS mount may not be on /, /bin, /sbin, /etc or anything below
    them: the network's own programs and files live there. In
    /etc/fstab the type is nfs (options: those of -o); mount -a mounts
    such a line without contacting the NAS (the first use does), so a
    boot never waits for a NAS, a cable or the network.

    mount -a mounts everything listed in /etc/fstab; init runs it at boot.
    Each line is "device dir type options" (fields separated by spaces or
    tabs): type is ext2, zenixfs, nfs (device host:/export) or auto (read
    from the partition type);
    options is defaults, or a comma list in which "noauto" leaves the line
    out of mount -a. Lines starting with # and empty lines are ignored.
    A line that fails is reported and the others are still mounted.

EXAMPLES
    mkdir /mnt
    mount ide0p1 /mnt
    mount -t ext2 ide0p2 /mnt/sub
    mount
    echo 'ide0p2 /data auto defaults' >> /etc/fstab
    mount -t nfs nas:/volume1/zenix /nas
    mount -t nfs -o soft,timeo=10 192.0.2.20:/export /mnt

EXIT STATUS
    0, 1 on an error (no such device, already in use or mounted, unknown
    type, the server did not start, directory missing; for mount -a, any
    line failed), 2 usage.

NOTES
    Once something is mounted, paths are resolved as text for the mount
    table: "." and ".." are removed from the path before it is looked up,
    and the kernel follows every symbolic link itself, into a mount and out
    of one (DESIGN D26). The mount point is recorded with its links
    followed (mount through /tmp/l with /tmp/l -> /tmp/mp lists /tmp/mp),
    so mount -l and umount see where it really is; a link to / or to a mount
    point is "device or resource busy", as / is. ".." written directly after
    a link is taken on the text (/bin/../etc is /etc with /bin -> /usr/bin;
    Linux gives /usr/etc). Hard links and renames across two mounts fail,
    decided by the names as written when they name two mounts (mv then
    copies). netd's files may lead through links into a disk mount, never
    into a network mount (netd would wait for itself). A link on a mounted
    volume can point at files elsewhere: the permissions checked are always
    the caller's, but mount only volumes whose names root may trust. Only
    the first 8 mounts fit, and 12 services in all (the disk and root
    servers included):
    beyond that mount says "too many filesystems mounted". A mount does not
    survive a reboot unless it is in /etc/fstab.
    A mount the kernel refuses says why (for example "not a directory",
    "device or resource busy" for a directory that is already a mount
    point, "permission denied" for a normal user); a server that did not
    start says "its filesystem server did not start (see dmesg)", and the
    service is removed again.
    ZenixFS names longer than 63 bytes (possible on a volume written
    elsewhere) are not listed by ls; they can still be opened by name.
    Only types with a server can be mounted (ext2, zenixfs, nfs). A ZenixFS
    mount needs /sbin/zfsd on the root: without it the server does not
    start ("cannot start /sbin/zfsd" in dmesg).
    NFS: reading only, for now (DESIGN D23 step 2): every change on an
    NFS mount is "read-only file system" until writing is built (step
    3). The NAS decides who may do what: NFSv3 trusts the uid the Amiga
    sends, so export the folder only to the Amiga's address and map
    every user to one NAS user (d23-nfs.md 8). Nothing on the wire is
    encrypted: the home network only. Set-user-id bits on the NAS are
    never honoured. Files of 4 GB or more cannot be opened; names
    longer than 63 bytes are not listed. A symbolic link on the NAS
    with an absolute target is followed from Zenix's / (as a Linux
    client does). A program changed on the NAS within the same second
    and to the same size as the copy in memory is not seen as changed.
    The NAS must accept a client on an unprivileged port when the
    Amiga is behind NAT (SLIP, the emulator): Linux's export option
    "insecure", the Synology's "allow connections from non-privileged
    ports". A host:/export may be up to 62 characters (fewer with
    options): the service table's room. A file that was open when
    nfscd was started again (a crash, or kill -9) answers "stale file
    handle" until it is closed; open it again.
    It asks the disk server for a device's details with DISK_INFOSZ or
    DISK_LISTSZ and its buffer's size, so a newer disk server never
    writes past it (the frozen-interface rule, CLAUDE.md).
