SVCTEST(1)		Zenix manual

NAME
    svctest - test the service manager

SYNOPSIS
    svctest port NAME
    svctest reg NAME NICE PROGRAM [ARGUMENTS]
    svctest rm NAME
    svctest call NAME TYPE [A0]
    svctest raw DEVICE
    svctest hold DEVICE SECONDS

DESCRIPTION
    A test program for the service manager (DESIGN D11,
    docs/d11-service-manager.md). Each use prints one line starting with
    "svctest" and the result (0 or more, or a negative error number):

    port   tries to create the message port NAME. A registered name
           (disk, fs) is refused with -16 (EBUSY) for everyone, root
           included: only the process the kernel started for it may
           take it.
    reg    registers the service NAME (root): PROGRAM is a built-in
           image (@diskd, @fsd, @zfsd) or an absolute path, NICE the
           server's priority. The first call to NAME starts it.
    rm     removes the service NAME (root).
    call   makes one call to the port NAME with message type TYPE (and
           a0) and prints the result and how long it took, in ms of
           the E-clock (emulator times are not hardware times).
    raw    opens DEVICE raw at the disk server, as fdisk or dd would:
           -16 while it (or a device sharing its sectors) is mounted.
    hold   opens DEVICE (plain), reads its first sector, waits SECONDS
           seconds and reads it again with the same handle: "svctest
           hold DEVICE: handle H, read R, after the wait R2". A disk
           server started again meanwhile must still know the handle.

    tools/svc-test.sh uses it in the emulator.

EXIT STATUS
    0, or 2 for a usage error.

SEE ALSO
