MKFS.EXT2(1)			Zenix manual

NAME
    mkfs.ext2 - make an ext2 filesystem

SYNOPSIS
    mkfs.ext2 [-b 1024|2048|4096] [-i bytes-per-inode] device

DESCRIPTION
    Writes a new, empty ext2 filesystem onto a partition (such as ide0p1),
    DESTROYING what was on it. The result is the original revision-0 ext2:
    128-byte inodes, no optional features, a superblock and group table copy
    in every block group. Linux can mount it and e2fsck reports it clean
    (checked with block sizes 1 KB and 4 KB, also over a device full of old
    data). The inode tables of all groups are zeroed: fsck reads every
    inode, and old data there would look like files. The device must not
    be mounted. The superblock gets a volume id (a uuid from the clocks):
    the filesystem server finds its volume by place and id after a
    restart.

OPTIONS
    -b size   block size in bytes (default 1024)
    -i n      one inode per n bytes of space (default 4096); a larger number
              gives fewer inodes, more room for data. Minimum 1024.

EXAMPLE
    fdisk add ide1 DH0 rest
    mkfs.ext2 -b 4096 ide1p1

NOTES
    Running out of memory is reported ("out of memory") and ends the command
    with a non-zero status; nothing is cut short silently. Its two block
    buffers are static, not on the stack: it runs in the default 16 KB.

EXIT STATUS
    0, 1 on an error, 2 usage error.

SEE ALSO
    fdisk(1), fsck.ext2(1)
