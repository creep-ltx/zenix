IFCONFIG(8)		Zenix manual

NAME
    ifconfig, ifup, ifdown - the network's interfaces

SYNOPSIS
    ifconfig [-a]
    ifconfig IFACE
    ifconfig IFACE [ADDRESS[/PREFIX]] [netmask MASK] [up | down]
    ifup -a [--boot] | IFACE...
    ifdown -a | IFACE...

DESCRIPTION
    The network server, netd(8), has the loopback lo (127.0.0.1) and the
    interfaces /etc/network/interfaces describes: SLIP on the serial
    port (the cable to a PC: docs/network-serial.md) and Ethernet cards,
    each run by its driver in /sbin/net (a2065(4), genet(4),
    ne2000(4), plipbox(4)). ifconfig shows them; root changes them. ifup and
    ifdown are other names of the same program.

    ifconfig            every interface: its flags (UP, RUNNING, LOOPBACK,
                        POINTOPOINT or BROADCAST (Ethernet), DEFAULT when
                        the default route leaves through it, DHCP), MTU,
                        the MAC address (ether), address, netmask,
                        gateway, the DHCP lease left and its server,
                        frames and bytes received and sent, bad frames
                        and dropped ones; then the name servers
    ifconfig IFACE      that one
    ifconfig IFACE up   brings it up as its stanza in the file says (as
                        ifup IFACE)
    ifconfig IFACE down takes it down (as ifdown IFACE)
    ifconfig IFACE 10.0.2.16/24
                        a new address (and netmask) on an interface that
                        is up, until netd starts again; connections on
                        the old address end
    ifup -a             brings up every interface with an "auto" line,
                        and looks for the cards no stanza names (CARDS
                        FOUND BY THEMSELVES below); as root, then starts
                        sntp(8) on its own (not waited for, its report
                        thrown away) when /etc/sntp exists
    ifup -a --boot      the same, as init(8) runs it at boot without
                        waiting: when there is no
                        /etc/network/interfaces, or it has an "auto"
                        line. When nothing is found and nothing is
                        configured, netd stops again and gives its
                        memory back (dmesg: "netd stops")
    ifdown -a           takes down every interface but the loopback

    ifup reads /etc/network/interfaces, /etc/resolv.conf and /etc/hosts
    again first. It returns as soon as the interface is configured: for
    a card, when its driver has started and attached (at most 10 s),
    not when a DHCP lease arrives (ifconfig shows "no lease yet").

/ETC/NETWORK/INTERFACES
    A small part of Debian's format; netd uses it only if root owns it
    and nobody else may write it (it starts programs as root from it).
    # starts a comment. A word netd does not know is reported in the
    kernel log (dmesg) and ignored.

    auto IFACE          bring IFACE up at boot (and with ifup -a)
    iface IFACE inet static
    iface IFACE inet dhcp
                        a stanza: the lines after it, indented, belong
                        to it; dhcp asks a DHCP server for the address,
                        netmask, gateway and name servers (cards only)
        driver slip DEVICE [BAUD]
                        SLIP on a serial device: /dev/ttyS0, at 115200
                        (the only speed of Zenix's serial port)
        driver NAME [ARGS]
                        a card: netd starts /sbin/net/NAME IFACE ARGS
                        (NAME without a /), e.g. "driver a2065"
        address A/PREFIX    the address and the size of the net
        gateway G       the default route
        pointopoint P   the far end, when it is not on the net
        mtu N           at most 1006 on SLIP
        hostname H      the machine's name (sent with DHCP)
    noprobe [NAME...]   netd never looks for a card with these drivers
                        (all of them without a NAME): for a printer on
                        the parallel port, "noprobe plipbox"

    The SLIP example (the PC runs zenix-slirp):

        auto sl0
        iface sl0 inet static
            driver slip /dev/ttyS0 115200
            address 10.0.2.15/24
            gateway 10.0.2.2

    With /etc/resolv.conf holding "nameserver 10.0.2.3", names are
    looked up through the PC too. An Ethernet card with DHCP:

        auto eth0
        iface eth0 inet dhcp
            driver a2065

CARDS FOUND BY THEMSELVES
    At its start and at every ifup -a, netd tries each shipped driver that
    no stanza names (genet, a2065, ne2000, plipbox, in that order, one at
    a time) as the next free ethN with DHCP. The looking is quiet, as on a
    Linux system: a driver that finds no card ends without a word (netd
    gives it the word "probe": it says nothing until its card is there)
    and is not started again. One that finds its card is an interface as
    if a stanza named it: "netd: eth0: /sbin/net/a2065 found a card: up
    with DHCP (no stanza in /etc/network/interfaces names it)". The kernel
    log gets one line when the looking is done ("netd: card probe done:
    found a2065; no card for genet, ne2000, plipbox"), or, when nothing
    was found and netd stops, that line names them. A stanza that names a
    driver shows the driver's own reasons for not finding a card in dmesg.
    A card a stanza names keeps its stanza (a static address, its own
    name); write one for a fixed address. Looking costs a moment of the
    driver's start each (the plipbox's about 0.7 s); a file with no "auto"
    line starts no netd at boot at all, and "noprobe" alone turns the
    looking off.

EXIT STATUS
    0 if everything asked was done; 1 if something was not (said on
    standard error: not root, no such stanza, already up, ...); 2 for
    wrong arguments.

NOTES
    While SLIP is up, the serial port is the network's: no cu(1), and
    the kernel's log stays in dmesg instead of going out on the cable;
    ifdown gives the port back. SLIP has no DHCP. A driver that ends
    five times in a minute is given up (dmesg says so) until ifup. If
    the network server was given up (five crashes in a minute), root's
    ifup or ifconfig ... up registers it again and says so. No aliases,
    no IPv6, no ARP probe of a DHCP address; ifconfig cannot change the
    MTU or the MAC address of a running interface.
