NFSCD(8)		Zenix manual

NAME
    nfscd - the server of an NFS mount

SYNOPSIS
    /sbin/nfscd nfsN host:/export [codes]

DESCRIPTION
    Not a command: mount -t nfs registers it as the service fs.nfsN and
    the kernel starts it at the mount's first use (DESIGN D23,
    docs/d23-nfs.md). It talks NFSv3 over TCP to the NAS and answers the
    kernel's file requests for that mount. Everything a user sets is
    mount's: see mount(8) for the options, hard and soft mounts, Ctrl-C
    on a NAS that is off, and the limits.

    codes is one word: s soft, tN timeo seconds, rN retrans, o read-only,
    y sync, aN actimeo, l lazy (the first use contacts the NAS; mount -a
    adds it). Its lines in dmesg start with nfsN: the source it serves,
    "the NAS is not answering, still trying", "the NAS answers again",
    a connection's error, a restart that finds another export.

EXIT STATUS
    0 after umount, 1 when killed or it cannot start, 2 for wrong
    arguments.

NOTES
    One process for each NFS mount, about 112 KB while idle on a machine
    without fast RAM (more as its cache fills, at most a 160 KB heap).
    For now it serves reading only (D23 step 2): every change answers
    "read-only file system".

SEE ALSO
    mount(8), umount(8), dmesg(1)
