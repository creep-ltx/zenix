FSCK.EXT2(1)			Zenix manual

NAME
    fsck.ext2 - check and repair an ext2 filesystem

SYNOPSIS
    fsck.ext2 [-y] [-n] device

DESCRIPTION
    Checks an UNMOUNTED ext2 filesystem the way e2fsck does, in five passes,
    and reports what is wrong. With -y it repairs what it safely can:
    block and inode bitmaps, free counts, link counts, directory entries
    pointing at unused inodes, ".." entries, file type bytes, a file's
    size that stops before its last block (as e2fsck: the size reaches it),
    and orphaned inodes (moved to /lost+found as #inode; an empty file
    nothing names is cleared instead, as e2fsck -p does). After attaching
    orphans it checks again by itself, at most 3 runs. A repair ends with
    a run that writes nothing and must find nothing; only then, and when
    the volume was clean from the start, -y marks it "cleanly unmounted"
    (the superblock's state, as its very last write, after a flush). A
    power cut during a repair leaves it marked, and the next run finishes
    the work. By default (or with -n) it only reports and never writes.
    It always checks first without writing. If it finds damage it cannot
    repair - duplicate or out-of-range block pointers, an invalid mode, a
    damaged directory block, a damaged resize inode, more than 512
    unreachable inodes - it repairs NOTHING and says so ("nothing was
    changed"): a half-done repair can make a disk worse. Use e2fsck then.
    An inode that looks used but is free in the inode bitmap counts as a
    file only if a directory names it (its bit is then set again).
    Directories are followed through all levels of indirect blocks.
    A device that the system has mounted is refused by the disk server.
    The root is checked by boot at the start when it was not shut down
    cleanly, and a volume /etc/fstab lists by mount -a (DESIGN D17,
    docs/d17-ext2-clean-mark.md); to check it at any other time, boot
    from other media. When boot's check cannot repair the root, the root
    stays read-only and fsck.ext2 may be run on it from the rescue shell
    boot offers (rescue(8)).

OPTIONS
    -y    repair what can be repaired
    -n    report only (default)

EXIT STATUS
    0 clean, 1 repaired, 4 errors remain, 8 operational error (cannot open,
    not ext2, out of memory, a repair write or the final mark failed),
    2 usage error.

NOTES
    Block sizes up to 4096 are supported, and the features of a modern
    "mke2fs -t ext2" (filetype, sparse_super, large_file, ext_attr,
    resize_inode, dir_index). A volume with an ext3 journal or any other
    feature is refused (exit 8): use e2fsck. Link counts up to 65535.
    Tested on the host against deliberate and random damage and against
    e2fsck (tools/ext2-host-test.sh): a repair never leaves more for e2fsck
    to fix than there was; e2fsck checks more fields than fsck.ext2.
    Running out of memory is reported ("out of memory") and ends the command
    with a non-zero status; nothing is cut short silently.
