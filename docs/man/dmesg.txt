DMESG(1)			Zenix manual

NAME
    dmesg - print the kernel message log

SYNOPSIS
    dmesg
    dmesg -p

DESCRIPTION
    Prints what the kernel has logged since boot: the same lines it writes to
    the serial port (CPU and memory map, the Pi hardware table, the Zorro
    boards, the disk found, driver messages, programs killed after a crash,
    and the service manager's "svc:" lines: every start of a server, for
    whom, and every end with its status). The servers' own messages are
    here too, and only here once the system is up: diskd's, the root
    filesystem server's ("fsd: ..."), a mount's ("fs.ide0p2: ...") and
    those of the services in /etc/svctab - their output goes into this
    log, not onto a console, so nothing writes over what you are doing.
    The kernel keeps the last 8 KB. The boot messages are also shown on the
    screen while the system starts (until the root filesystem's server is
    up); scroll back with Amiga+Up if they have
    gone by. dmesg is how to read them again on a machine with
    no serial cable.

    -p  Print the log of the previous boot instead: the kernel keeps its log
        at the top of chip RAM, and after a warm reset (Ctrl-Amiga-Amiga) the
        next boot finds it there. This is how to see why a boot froze or
        panicked. While booting, the kernel already shows its last 20 lines
        (marked "> ") between "=== previous boot (N) ended here" and
        "=== end of the previous boot's log ===". If the previous boot's
        log text fails its checksum, the kernel says only how that boot
        ended ("its log text is damaged") and -p finds no log.

EXIT STATUS
    0, or 1 for -p when there is no log from a previous boot (after a power
    off, or when the memory did not survive the reset); 2 for a wrong option.

NOTES
    The log holds the last 8 KB of this boot's messages; once it has
    wrapped, dmesg starts at the oldest character still there (each
    message shown once). Not done: clearing the log, following it as it
    grows, a level or a time stamp per message. Output is plain text, one
    kernel message per line. Whether chip RAM survives a warm reset on a
    PiStorm is not yet known.
