TERMTEST(1)			Zenix manual

NAME
    termtest - terminal feature test

SYNOPSIS
    termtest [columns|colours|scroll|pcfont [FILE]|rules TTY]
    termtest [conops|rawkeys|text|readline|readraw N|grab FILE|depth N]
    termtest screen TTY TEXT SECS [TYPE]

DESCRIPTION
    Draws a test page: bold, underline and inverse text, a 36-column box
    drawn with cursor addressing (its text clear of the borders), a scroll
    region, line erase, and line insertion. It then
    switches the terminal to raw mode and shows each key you press as the
    escape code or byte received (arrows, function keys, Delete). Press q to
    quit. A development tool.

    The other pages are for the screenshot tests (tools/colour-test.sh):
    termtest columns: rows 1-7 number the 80 columns in binary (a lit
    cell is a set bit, row 1 the lowest), row 8 is lit across all 80; q
    quits. termtest colours: the 16 colours as blocks (rows 3-4, five
    columns each) and as text on black and on white, with bold, underline
    and inverse, a 256-colour and a true-colour sample; q quits. termtest
    scroll: 100 coloured lines (every fifth erased to the line's end with
    a background colour), then a scroll region with inserted and deleted
    lines; it ends by itself. termtest pcfont: loads FILE (a PSF1 font)
    or a test font of its own (each glyph shows its byte's two hex digits
    as wide bits) as the console's font, sets the BBS rules and draws all
    256 bytes as glyphs, the CGA palette's 16 blocks, a bright and an iCE
    sample, a wrapped full row and a line feed without carriage return
    (the rows are listed in user/termtest.c); q clears the screen, drops
    the font and the rules and quits, x quits at once (the kernel then
    drops them), 2 4 8 6 switch the display to 2, 4, 8 or 16 colours
    (root). termtest rules TTY: prints the console rules (CON_RULES
    bits) of the console TTY, such as /dev/tty1 (root, for another
    console), for telnet's tests. In termtest colours, g writes the
    display to /tmp/grab.zg (as grab below).

    The console operations of the remote control (root; tools/con-test.sh,
    DESIGN D24 6.1-6.3): termtest conops draws a page and checks it
    through CON_READ (the grid, the cursor, the change counter, short
    buffers, the errors, an unknown op 10: EINVAL; 8 and 9 are DESIGN
    D38's CON_GRAB and CON_GACK) and CON_LINE (pens and palette), and that
    a console never used answers ENXIO; termtest rawkeys types raw key codes
    through CON_INPUT and checks the bytes (the Swedish layers, Caps
    Lock, Ctrl, an arrow, what a call leaves held released, Amiga+F2 and
    back); termtest text types through CON_INPUT in raw and cooked mode
    and prints the bytes read as "raw:HEX" and "line:HEX", as termtest
    readline (one cooked line) and readraw N (N raw bytes) print what was
    typed on the console, so the two paths compare. Each prints PASS and
    FAIL lines and "NAME: N failed", exit status 1 on a failure.
    termtest grab FILE writes the shown display through CON_LINE: ZGRB,
    the width, height and depth (16 bits each), 16 palette words
    (0x0RGB), then a pen a pixel. termtest depth N switches the display
    to N colours (2, 4, 8, 16; CON_COLOURS). termtest screen TTY TEXT
    SECS waits (at most SECS seconds) until TEXT is on the grid of the
    console TTY, such as /dev/tty1, and has not changed for 200 ms, then
    prints it through CON_READ:
    "row NN|...|" per row, "attr NN|...|" for a row with colours or
    attributes ('.' a plain cell, else the hex digit of its foreground
    colour), and the cursor; exit status 1 if TEXT never came; then it
    types TYPE into that console (\xHH and \r for control keys, \kHH
    for a raw key code: 60 42 c2 e0 is Shift+Tab), so a test goes on
    only once the grid was read (tools/sumi-test.sh).
