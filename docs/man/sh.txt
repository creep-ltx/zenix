SH(1)			Zenix manual

NAME
    sh - the Zenix shell

SYNOPSIS
    sh [file [argument...]]      run a script
    sh -c 'commands' [name [argument...]]
    sh                           commands from standard input
    sh -i                        an interactive shell even without a
                                 terminal

STANDARD INPUT
    With no file and no -c the shell reads its commands from standard
    input. As bash, it is interactive (prompts, the line editor, history,
    the start-up files, job messages such as [1] 23) only when standard
    input and standard error are both terminals, or with -i. Otherwise,
    as when a pipe or a file is its input (echo id | su anna, sh < file),
    it prints no prompt and reads the input like a script, one command at
    a time, so a command it runs reads the rest of the input:
    printf 'read x\nhello\necho $x\n' | sh prints hello. From a pipe it
    reads one byte at a time, so it never takes more than the next
    command; from a file it reads a block and moves the file's position
    back to the end of the command before running it. A syntax error ends
    the input there (status 2), as in a script.

LINE EDITING
    Left, Right      move
    Ctrl+Left, Ctrl+Right (Home, End)   start / end of the line
    Ctrl+A, Ctrl+E   start / end         Ctrl+B, Ctrl+F   back / forward
    Alt+Left/Right   a word back / on
    Backspace, Del, Ctrl+D   delete (Ctrl+D on an empty line ends the shell)
    Ctrl+K   cut to the end              Ctrl+U   cut to the start
    Ctrl+W   cut the word before         Ctrl+T   swap two characters
    Up, Down (Ctrl+P, Ctrl+N)   earlier and later commands; the history is
             kept in ~/.sh_history (a command longer than the 478
             characters the line holds comes back cut, with the bell,
             and does not run)
    Tab      complete a command, a file name or a $variable; twice lists
             the choices, a path's by their last part (Latex/ Loonies/,
             as bash shows them)
    The line is UTF-8 (the console's): the keys move, delete and swap
    whole characters, and wide characters take two columns; a byte that is
    not UTF-8 is one character of one column, as the console shows it.
    The 478 characters the line holds are bytes (a Swedish letter is two).
    Ctrl+R   search the history backwards as you type; Ctrl+R again goes to
             an older match, Enter runs it, an arrow key keeps it for editing,
             Ctrl+G cancels
    Ctrl+L   clear the screen            Ctrl+C   cancel the line
    What is typed while a command runs is kept and appears at the next
    prompt (as on a Unix tty).
    Each key redraws only what changed on the line, in one write (a key
    typed at the end writes that character alone). Text another program
    writes onto the line while you edit stays until Ctrl+L redraws it (as
    in bash).
    Every byte from 0x80 to 0xFF typed or pasted is text (part of a UTF-8
    character, for instance); only the Del key itself deletes.
    A line holds 478 characters. A key typed past that rings the bell and
    is not taken, and Enter then does not run the line: "sh: the line was
    too long (more than 478 characters): not run", status 2. Go on over
    several lines with a backslash at the end of each (2047 bytes in all).
    A line typed ahead while a command runs is refused the same way past
    the tty's 511 characters ("tty: the line was too long").

LANGUAGE
    Commands:   name arg...   a program found in $PATH, a builtin, a
                function or an alias
    Variables:  NAME=value    $NAME ${NAME} ${NAME:-default}
                ${NAME:=default} ${NAME:+other} ${#NAME}
                ${NAME#pat} ${NAME##pat} ${NAME%pat} ${NAME%%pat}  remove a
                prefix / suffix (shortest, longest) matching a pattern
                ${NAME/pat/new} ${NAME//pat/new}  replace first / all
                ${NAME:offset} ${NAME:offset:length}  part of the text (a
                negative length counts from the end; one that ends before
                the offset is an error, "substring expression < 0", as bash)
                $? status of the last command   $$ shell pid
                $# $1..$9 ${10}... $@ $* the arguments   $! last background
                pid
    Quoting:    'literal'  "with $expansion"  \x escapes one character
    Expansion:  $(command) or `command` the command's output;
                $((1+2*3)) arithmetic (names, $name, ${name}, $1, $# inside
                are their values);  ~ the home directory
    Wildcards:  * any text  ? one character  [abc] [a-z] [!a]
                (names starting with . need a literal .; a symbolic link
                that leads nowhere matches too, as in bash)
    Braces:     pre{a,b}post gives preapost prebpost; {1..5} {a..e} {01..10}
                {1..10..3} (not inside quotes)
    Pipes and lists:  a | b   a && b   a || b   a ; b   a &   ! a
                ( a; b )   { a; b; }
    Redirection:  < file   > file   >> file   2> file   2>&1   &> file
                N>&M for fds 0-9 (3>&1 1>&2 2>&3 swaps; fd 3 is closed
                again afterwards)
                <<WORD (a here-document; <<-WORD strips tabs)
                after a compound command too, for all of it:
                ( a; b ) > file &   { a; } 2>&1 | b   done < file
    Conditions: if list; then list; elif list; then list; else list; fi
    Choices:    case word in pattern|pattern) list ;; ... esac
                (patterns are wildcards; the first that matches runs)
    Loops:      while list; do list; done    until list; do list; done
                for x in words; do list; done
    Functions:  name() { commands; }   return [n]   break [n]   continue [n]
    Scripts:    first line  # comments;  sh file   or   . file
    A command that is only a variable assignment (A=1) sets a shell
    variable; A=1 command passes it to that command only.

BUILTINS
    cd [dir|-]  exit [n]  export NAME[=value]  unset NAME  set [-- args]
    alias [name=value]  unalias name  history [-c]  source file (or . file)
    read [-p prompt] name...  shift [n] (n >= 0)  return  break  continue
    jobs
    fg [%n]  bg [%n]  wait [pid|%n]  kill [-SIGNAL] pid|%n|-pgid  kill -l
    type name
    test expr (or [ expr ])  true false :  echo [-ne]  pwd  eval
    (echo: a write that fails, a full disk, says "sh: echo: write error"
    and the reason, status 1)
    local NAME[=value] (in a function only: the old value comes back when
    the function returns, as in bash)
    help  umask [mask]  trap ['commands' | '' | -] SIGNAL...  trap [-p]
    test: -e -f -d -r -w -x -s -z -n -L, = != -eq -ne -lt -le -gt -ge,
          ! -a -o ( )

VARIABLES THE SHELL USES
    PATH (default /bin)  HOME  USER  HOSTNAME  IFS  PWD  OLDPWD
    (PWD, pwd and the prompt's \w are the system's working directory,
    up to 255 bytes, with no symbolic link in it: after cd through a link
    they show where it led, as Linux's cd -P; DESIGN D26)
    TERM (default xterm-16color: the console speaks xterm's keys and 16
        colours; over a serial line the other computer's getty sets it)
    LANG (default C.UTF-8: the console's one character set; programs on
        the C library read it with LC_ALL and LC_CTYPE; LANG=C gives bytes)
    NO_COLOR (set to something: no colours from ls, grep, edit or the
        prompt; no-color.org)
    LINES (from the terminal: 32 on PAL, 25 on NTSC)  COLUMNS
    PS1 (the prompt: \w directory, \W its name, \u user, \h host,
        \$ # or $, \n, \e ESC, \[ \] around codes that take no room;
        default \h:\w\$ with the host green and the directory blue on a
        terminal with colours - the rule of ls --color=auto)
    PS2 (the continuation prompt, default "> ")
    At the prompt, a command that is not finished yet (an open quote or
    here-document, if without fi, a loop without done, case without esac,
    a function, { or ( without its end, a line ending in | && || or a
    backslash) is continued on the next line after PS2, as in bash; Ctrl+C
    there drops it. A command typed this way is at most 2047 bytes.
    Start-up files: /etc/profile and ~/.shrc (read by an interactive shell
    only: not by a script, sh -c or commands from a pipe).
    ~/.shrc is read only if it belongs to the effective user or to root, so
    a shell that runs as root never runs another user's start-up commands.

JOBS
    command &   runs in the background; jobs lists them (Running, Stopped,
    Done); wait waits; kill %1 sends SIGTERM to one (kill -NAME %1 another
    signal). An interactive shell puts every job (a command or a whole
    pipeline) in a process group of its own and makes it the terminal's
    foreground while it runs, so Ctrl+C (SIGINT) and Ctrl+Z (SIGTSTP) reach
    every process of it and nothing else; Ctrl+C during a loop the shell
    itself is running stops the loop. Ctrl+Z stops the job and gives the
    prompt back: bg lets it run on in the background, fg brings it back to
    the foreground (both send SIGCONT; the job is %n from jobs; without a
    number the most recent one). A program may catch these signals (less
    and edit leave the screen tidy and draw it again when continued). The
    shell itself is its own group and is never stopped by Ctrl+Z. When its
    terminal hangs up (SIGHUP: the program holding a pseudo-terminal's
    master closed it), an interactive shell sends SIGHUP and SIGCONT to
    every job and ends with status 129, as bash does.

SIGNALS
    trap 'commands' SIGNAL... runs the commands when the signal arrives,
    after the command that is running ends (as bash); $? is kept. trap ''
    SIGNAL ignores it (also in the commands the shell starts), trap -
    SIGNAL (or trap SIGNAL) puts the default back; EXIT (0) runs when the
    shell ends. trap and trap -p [SIGNAL...] list them, trap -l the names.
    SIGNAL is a name (INT, SIGINT) or a number; KILL and STOP cannot be
    trapped.

NOTES
    There is no fork. A builtin, a function or a ( ) group in a pipeline, and
    every $( ), runs in a child shell that is given the text of the command
    plus the variables, functions and positional parameters it uses, so it
    sees what the parent sees; changes it makes stay in the child. The shell
    keeps within its 16 KB stack and answers "nested too deeply" instead of
    running over it (a function that calls itself without end).
    Unlike bash, a loop does not stop when a command in it was ended by
    Ctrl+C (status 130). A script or sh -c is not interactive: its commands
    stay in its own group (the job its parent shell made).
    Brace and pattern text inside quotes is literal. Not done: [[ ]], arrays,
    history expansion (!!), here-strings, process substitution, getopts.
    An error says why: "permission denied", "no such file or directory",
    "argument list too long" (a program takes at most 256 arguments and
    8 KB of them) ...
    No silent limits: the number of arguments, wildcard matches, words in a
    command, pipeline stages and for-loop items grows as needed (in the
    shell's work area, which starts at 8 KB, grows while a command needs more
    and gives it back when the command is done; when memory runs out the shell
    says "out of memory" and ends, status 2). A script (sh file, . file, the
    start-up files) is read and run one command at a time, so its length does
    not matter: a syntax error ends it there, after the commands before it
    have run. A word longer than 4095 characters, more than 8 here-documents
    on one line, more than 64 local variables or more than 16 aliases
    expanding into each other are errors (status 1, or 2 for the
    here-documents), never a silent cut. A here-document's text after
    expansion has no length limit. An alias is not expanded again inside
    its own expansion (alias a=b b=a ends with "a: command not found", as
    bash). Arithmetic nested too deeply is an error. Each round of a loop
    gives back what it used, so a long while-read loop runs in the same
    memory.
    Not done: redirections of fds 3-9 to files (only N>&M).
    A here-document is kept in /tmp/.shPID_XXXXXXXX (random letters),
    created exclusively and readable only by the user, and removed when
    the command ends.
    A variable, alias or EXIT trap that is unset or replaced gives its memory
    back, so a shell that runs for a long time does not slowly run out of
    memory. When there is no memory for a new value, the shell says so and the
    variable keeps its old value.
    sh is a program with shared code: one copy of its 71 KB of code in
    memory serves every shell (each console's, each sh -c, each command
    substitution); each shell has only its own data, stack and work area
    (ps shows the code as SHR, free as shared code).
