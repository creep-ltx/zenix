DISPLAYD(8)		Zenix manual

NAME
    displayd - the display server of Zenix Desktop

SYNOPSIS
    /sbin/displayd [-persist]

DESCRIPTION
    The display server (DESIGN D38, docs/d38-desktop.md). It is the
    service "display" in /etc/svctab: the first program of the desktop
    that calls it starts it (zdesk, or any program using libdisplay). It
    takes the text console of that first program from the kernel
    (SYS_console CON_GRAB) and owns the screen, the blitter, the keyboard
    and the mouse while that console is shown. Amiga+F1..F10 still show
    the other consoles; it lets go of the screen when asked and takes it
    back when its console is shown again.

    It draws everything: the windows' frames from the window manager's
    style (without one, a plain built-in style), the programs' drawing
    orders, sent in batches and checked one by one, and the pointer (the
    hardware's sprite 0, moved by the kernel). The screen is 640 x 256
    (640 x 200 on NTSC) in 16 colours on AGA, 8 on OCS and ECS.

    Smart refresh: a window that is partly covered keeps a copy of its
    inside in chip RAM, so raising, uncovering and moving it never ask its
    program to draw again. Those copies have a budget of 256 KB; past it a
    window is simple refresh: what is uncovered is cleared and its program
    asked to draw it (EV_EXPOSE).

    It draws only what changed, each pixel once where it can (a frame's
    title bar beside its title, the title's cells, the gadgets after;
    a copy of whole 16-pixel words is one blit of every plane, the
    blitter's B to D). Its counters of blits, pixels, glyphs, batches,
    damage painted and copies onto the screen, and a whole drag's moves,
    shows and their times (DPY_STAT; dpytest's stat) are how the tests
    check what an action costs.

    Drags run in the server. On AGA a move is done by the chips: the
    window is lifted into the second playfield (dual playfield, 4 + 4
    planes) and each move rewrites a few Copper words, in a list the
    Copper takes at the top of a frame, so it moves at the frame rate on
    any CPU, never torn, with no blit; on the drop it is drawn back into
    the screen. It takes chip RAM for the drag only: (the window's width
    in bytes + 88) x 4 planes x its height (about 81 KB for 400 x 140).
    Pen 0 is transparent in a playfield: a window using pen 0 has those
    pixels shown in an unused pen of pen 0's colour (one using all 16
    pens, a resize, OCS/ECS or no chip RAM: the ways below, as the frame
    style's drag setting says). Otherwise an outline (XOR lines, the
    window moved once at the release) or the whole window. A whole
    window's drag draws into a second screen in chip RAM (80 KB at 4
    planes, for the drag only) and shows what changed once a pass, at
    most one move a pass whatever the mouse did meanwhile: one copy of
    whole words, started where the raster can neither overtake it nor
    come round to meet it before it ends, so every frame shows the
    window whole at one place. A part the
    move uncovered that a program draws itself (the desktop, a simple
    refresh window) is shown when that program has drawn it, or after
    60 ms. Without the chip RAM for the second screen the drag is an
    outline.

    Without a window manager new windows are placed one below the other, a
    click raises and focuses a window, its title bar drags its outline and
    its close gadget asks the program to close it.

    It ends when its last client has gone, and the console is text again.

OPTIONS
    -persist  stay when the last client has gone (a login manager's)

FILES
    /etc/svctab                       its service line
    /usr/share/consolefonts/zenix-8x8.zcf   the characters beyond Latin-1

NOTES
    Only the first client's user (and root) may use the desktop, or the
    user a login manager (root's, dlogin(8)) names with DPY_SESSION; a
    change drops the clients of every other user. Only the
    console of the first client is taken: a program on a pseudo-terminal
    or a service cannot start the desktop. One font: the console's (Topaz
    8 from the kernel, the Unicode supplement); a wide character draws as
    one cell. At most 32 windows, 16 client programs and 48 images (64 KB
    of chip RAM a program); a window's visible part is at most 24
    rectangles (more: the change is painted whole and the programs asked
    to draw). A program's events go only into its own ring (the port it
    names must be its own). The protocol is display/proto.h.
