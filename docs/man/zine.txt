ZINE(1)				Zenix manual

NAME
    zine - run an AmigaOS program under Zenix

SYNOPSIS
    zine [--blob FILE] PROGRAM [ARGS...]

DESCRIPTION
    Runs PROGRAM, an AmigaOS executable, under ZINE: Zenix pauses, gives
    the program the machine and a small AmigaOS of its own
    (/lib/zine/zine.blob, loaded only when zine runs), and carries on at
    the prompt when the program ends. The disks are written out first;
    every Zenix program is paused where it stood while the Amiga program
    runs.

    Root and the members of the group zine may run it (root adds one
    with gpasswd -a NAME zine; it counts from their next login or su),
    and only at the Amiga's own console (not over ssh or telnet). zine is
    set-user-id root; it reads the program and its folder only where the
    user who ran it may, with that user's groups. A
    member of zine can do anything to the machine while a program
    runs, as root can. It needs fast RAM.

    An AmigaOS program with the x bit runs by its name too, as any
    command: the kernel sees the file starts with 00 00 03 F3 (an
    AmigaOS executable) and runs zine PATH ARGS... instead. Without the
    x bit it runs only as zine FILE.

    While zine writes the disks out and the program runs, other
    programs' file requests wait (they go on when Zenix is back). If any
    local disk cannot be written out, zine refuses; Ctrl-C during that
    gives up before anything is handed over. Afterwards every floppy
    drive's disk counts as changed (the program may have swapped it):
    open it again before using it.

    On a 68040 or 68060 (and the PiStorm's Emu68) a 68030 MMU
    instruction an old program uses to switch the MMU off (PMOVE,
    PFLUSH, PTEST) is taken as a no-op, as the MMU is off. On a 68040
    or 68060 the instructions the CPU lacks are emulated for the
    session by Motorola's packages, /lib/zine/sp040 and sp060 (FSIN,
    FCOS, FETOX, FMOVECR, packed decimal, denormals, ...; on the 68060
    also 64-bit MULU.L/DIVU.L, MOVEP, CAS2, CHK2), as 68040.library and
    68060.library do under AmigaOS; the program's output says so first.
    Not on Emu68 (it runs them itself), and not on an EC/LC part
    without an FPU (only the 68060's integer ones there); a program
    that needs an FPU then crashes, the crash line naming the
    instruction. CacheControl switches the instruction cache; the data
    cache stays off. A program that switches it on itself still writes
    chip RAM straight through (Zenix keeps the first 16 MB uncached).
    MOVEC to or from CAAR (a 68020/030 register) is a no-op there, and
    AttnFlags say the FPU when the package has one.

    Overlaid programs (a root that loads its other parts from its own
    file while it runs, as many demos of the 1990s do) run: the whole
    file is in memory during the session, and the program's overlay
    supervisor loads each part from there. zine says so first
    ("NAME is overlaid: N later parts ..."). A program whose file and
    hunks do not fit in memory together is loaded by zine from its
    file before the hand-over, and its file is not kept (zine says so);
    that cannot be done for an overlaid program, or for chip RAM hunks
    larger than the chip RAM Zenix has free at the moment: zine says
    which and refuses.
    A program may also send packets to its file's handler itself (as
    crunchers do through the overlay file): ZINE answers reading,
    writing, seeking, closing and flushing.

    dos.library's Execute runs a command that names a program file (in
    the program's folder or a subfolder, C: or an assign; any case),
    as demos made of separate programs need: loaded, given its
    arguments, its own stack and the redirections (>NIL:, <file,
    >>file), run to its end and unloaded; its return code is IoErr().
    It runs on the same task: after "run" too, the program waits for
    it. A command run that way may run others, 8 inside one another at
    most.

    A program may run more than one task: exec AddTask and dos
    CreateNewProc or CreateProc start one, and ZINE switches them as
    AmigaOS does (the highest priority first, equals in turn, a task
    that waits gives the CPU to the next). Nothing of Zenix runs
    meanwhile. The session ends when the program's first process ends,
    whatever its other tasks are doing.
    A command of AmigaOS's Shell or C:
    (CD, Echo, Stack, SetPatch, LoadWB...) is not run: Execute answers
    "done". A name that is no file answers "failed". The output names
    each command and what was done. An Assign command ("Assign LIBS:
    Ram:", also as "C:Assign" or "Ram:Assign") ZINE does itself: up to
    8 names of up to 3 directories each.

    A program may write files on any path (RAM:, T:, ENV:, its own
    folder, SYS:, DH0:), read them back by that path, load and delete
    them; they live in its own memory and are gone afterwards. Nothing
    reaches a disk: a file it writes or deletes in its own folder is
    changed in memory only, the disk keeps the real one.
    OpenLibrary of a library ZINE does not have loads it from LIBS:
    (at the start the program's LIBS directory, its own directory and
    RAM:), as demos that carry their own library do. audio.device
    gives out the four channels and plays what is written to it
    (CMD_WRITE), as demos with a sound process of their own need.

    The program sees its folder and its subfolders (8 levels deep, at
    most 2000 files and folders, 48 MB, and half the fast RAM the program
    leaves free), copied into memory first. A bigger folder: its
    archives and disk images are left out first, then its largest
    files, each named (a program that loads one will not find it);
    with more than 2000 entries only the program goes in. Names
    are found without case, as on AmigaOS (data/xyl.tp3 finds
    Data/XYL.TP3; the Latin-1 letters too). Two names in one folder that
    differ only in case (AmigaOS has no such pair) are both kept: a name
    the program uses finds the one spelt exactly so, else the first
    found; zine says so once, before the program starts. A file name
    on the Zenix disk that is not UTF-8 is taken as Latin-1 bytes.

    ZINE also has utility.library and the math libraries (mathffp,
    mathtrans, mathieeesingbas/-singtrans, mathieeedoubbas/-doubtrans,
    computed in software), and topaz 8 as the ROM font (its glyphs are
    Zenix's own).

    Fonts on disk (diskfont.library): copy AmigaOS bitmap fonts into
    /usr/share/fonts/amiga as they are in FONTS: (NAME.font and its NAME
    folder). zine puts them into the program's FONTS (its own Fonts
    folder, if it has one, comes first) when they fit beside its files;
    else it says they were left out. A font the program asks for and
    does not find is named with its size and where to put it, e.g.
    "ZINE: demo needs xen.font size 8: copy it into
    /usr/share/fonts/amiga". A size the font lacks: the nearest is
    given and said (AmigaOS would scale it). A damaged font file is
    refused with its reason.

    The program's folder is read-only: Lock, Examine and ExNext list
    it as it was at the start (files written during the session are
    kept, but not listed there); CurrentDir changes where names
    without a device are found.
    A disk name the program asks for that ZINE does not have (a demo
    that opens "Love:data") is taken as the program's own folder, as
    "Assign Love: <its folder>" would; zine says so once.
    On a machine with an FPU the math libraries compute on it.
    console.device opened on a window takes the program's text into its
    output (control sequences left out); it gives no keys, so a read
    waits; input.device takes a program's input handler and never
    calls it. The first large AllocMem that fails is said, with the
    largest free block (a program that quits at once for want of
    memory shows why).

    ZINE is being built (DESIGN D29): real demos run in FS-UAE.

    Ctrl-Amiga-Amiga while the program runs restarts the machine into
    Zenix.

OPTIONS
    --blob FILE   use FILE instead of /lib/zine/zine.blob (the tests'
                  /tests/zine/null.blob pauses and resumes only)

EXAMPLES
    zine /home/demos/mydemo
    chmod +x mydemo; ./mydemo      (the same, by name)

EXIT STATUS
    The program's return code; 1 when it could not run, crashed or was
    stopped; 2 for bad arguments.

SEE ALSO
