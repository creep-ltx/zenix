MSGPINGD(1)		Zenix manual

NAME
    msgpingd - test message server

SYNOPSIS
    msgpingd [-port NAME] [-call NAME] [-uid N] [-old] [-paula]
             [-fs | -fsstall | -fsbad | -fslinked | -fsdir | -fswin]
             [count]

DESCRIPTION
    Creates a message port named "ping" and answers the requests of
    msgping(1): type 1 adds two numbers, type 2 converts a string to upper
    case IN PLACE in the client's memory (showing that messages pass
    pointers, not copies), type 3 answers with what the service manager
    told it at its start (the start count, plus 65536 if the last server
    ended in the middle of a request), type 7 waits a second and then
    crashes (an illegal instruction: for the service manager's tests),
    type 9 ends the server, type 10 rewrites the client's own message
    (whose address the client puts in a[0]) while it serves it and then
    answers 7 with a[2] 4242 (with memory protection on the kernel must
    not use what the client's memory says: DESIGN D60 5.1), type 11
    writes the byte a[1] bytes after a[0], type 13 asks the kernel for 4
    bytes at a[0] (SYS_peer PEER_RD, the answer in a[2]), type 14 writes
    a[0] without asking (msgping past, peer, wild). It also ends
    after serving count requests if given. Start it in the background:
    msgpingd &
    -port NAME  serve port NAME instead of "ping".
    -uid N      serve as user N (root only): a server that may not see
                a root client's memory.
    -old        open the port without marking it PEER_EXACT: an old
                server (DESIGN D60 5.8), which with memory protection on
                gets its client's whole memory when it could debug the
                client, and refuses the request with -13 when it could not
                (with -uid N and a root client). Without it, it sees only
                what its clients declare.
    -paula      (registered as the service "audio": svctest reg audio 0
                /bin/msgpingd -port audio -paula) claim Paula and try the
                kernel's checks of DRV_AUDIO (DESIGN D60 6.2): a channel in
                the kernel's memory, past its own chip RAM, in its fast RAM,
                DMAEN, an AUDxLCH alone, a channel playing from a block it
                then frees; one line "msgpingd: paula ..." with the
                answers, then it writes Paula itself, which with memory
                protection on ends it (tools/mmu-test.sh).
    -call NAME  call port NAME once before opening its own port (a server
                whose start needs another service; D11's tests use it to
                make a cycle).
    -fs         be a filesystem server that hangs: it answers the request
                for its root directory, never answers a sync, ends at the
                quit of umount and refuses the rest (svctest mount puts
                it on a directory; the reboot test uses it).
    -fsstall    the same, but it never answers any request but its root,
                a close and the quit: a program that opens a file there
                waits in the kernel until the server ends (wasabid's
                "freed": tools/remote-test.sh).
    -fsbad      as -fs, but the request for its root fails too: a
                mount that fails must end its server.
    -fslinked   a filesystem server that gives DESIGN D26's "the path
                continues elsewhere" answer wrongly: to an open (but of
                its root and of /f) with bits no one-path request may
                have, to a read and a directory read, which never ask for
                it, and unchanged to the rest; it answers its root, a
                sync, a close and the quit (the kernel must refuse the
                wrong ones with an I/O error: tools/mounttest.sh).
    -fsdir      an older filesystem server (DESIGN D49): its root lists
                ".", ".." and n00 .. n49 through FS_READDIR only and
                answers FS_READDIRS "not known", so programs read it
                one record a call (tools/readdir-test.sh).
    -fswin      a filesystem server for the memory protection tests
                (DESIGN D60 stage 2, tools/mmu-test.sh): its files f,
                fwd, over, under, after, forge and where are 20000 bytes of
                the pattern (i * 7 + i / 256) & 255; f is read as asked,
                fwd read by the server from /tmp/wsrc straight into the
                client's buffer, over writes one byte past the buffer,
                under one before it, after keeps the buffer and writes
                into it at its next request that is not a read; a stat of
                forge tries a reply to a forged address, then a second
                reply, and prints what each got; a stat of where prints
                whether its path argument is a copy in its own message.

    A development tool; see docs/architecture.md, "Ports and messages".
