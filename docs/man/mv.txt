MV(1)			Zenix manual

NAME
    mv - move or rename files

SYNOPSIS
    mv [-fv] source... destination

DESCRIPTION
    Renames the source to the destination. With more than two names the last
    must be a directory and everything is moved into it. If the destination
    is an existing directory the source is moved into it. Only when the
    rename cannot be done because the destination is on another filesystem
    (another mount; on ext2 also a directory moved to another parent) does mv
    copy the tree and remove the original. Any other refusal (permission
    denied, a non-empty directory in the way) is reported and nothing is
    copied: "mv: cannot move SOURCE to DEST: REASON".

OPTIONS
    -v    print "'source' -> 'destination'" for each move
    -f    accepted (no effect)

EXAMPLES
    mv old new
    mv *.txt docs

NOTES
    When mv copies (another mount) onto the source itself (a symbolic link
    back onto the source's own mount), it refuses before writing: "mv: 'A'
    and 'B' are the same file", and the source stays. A rename onto the
    same file is left to the filesystem (FAT's "mv readme README" works).
    Directories with any number of entries are walked, as deep as paths go. A
    path longer than 255 bytes (what a system call takes) is reported
    ("file name too long") and skipped, never cut short.

EXIT STATUS
    0, 1 if something could not be moved, 2 usage error.

SEE ALSO
    cp(1), rm(1)
