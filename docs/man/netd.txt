NETD(8)		Zenix manual

NAME
    netd - the network server

SYNOPSIS
    /sbin/netd        (started by the kernel, never by hand)

DESCRIPTION
    netd is Zenix's TCP/IP: lwIP 2.2.1 (BSD licence, its notice in
    /usr/share/licenses/lwIP) with Zenix's own layer around it (DESIGN
    D19, docs/d19-network.md). It is the service "net": boot registers
    it when /sbin/netd exists, and the kernel starts it the first time
    a program opens a socket, or at boot (init's ifup -a --boot) to look
    for network cards: when it finds none and nothing is configured it
    stops again, so a machine without a network gives its memory back.
    Programs never talk to netd directly: they use the BSD socket calls
    (socket, connect, send, ...), the kernel checks
    every pointer and does every wait, and netd answers each request at
    once, so ^C and poll work on sockets as on pipes.

    What it carries: TCP, UDP, ICMP echo sockets (ping(1), for every
    user), the loopback 127.0.0.1, and SLIP on the serial port: the
    interfaces of /etc/network/interfaces (ifconfig(8); the cable to a
    PC: docs/network-serial.md). Names come from /etc/hosts, then DNS
    (the name servers of /etc/resolv.conf). Ports below 1024, the
    interfaces and the routes are root's.

    At its start netd opens its port, then reads /etc/hosts,
    /etc/resolv.conf and /etc/network/interfaces (the last only if root
    owns it and nobody else may write it) and brings up the interfaces
    with an "auto" line, then looks for the cards no stanza names (each
    shipped driver in turn, as ethN with DHCP; ifconfig(8), CARDS FOUND
    BY THEMSELVES; the kernel log says what it found); ifup reads them
    again. SLIP opens /dev/ttyS0
    without ever waiting on it: what does not fit the port's send ring
    waits in netd's own queue. SLIP has no checksum of its own, so netd
    checks every frame from the line (the IPv4 header and the TCP, UDP
    or ICMP sum): a frame damaged by noise is counted (ifconfig's "bad")
    and dropped.

    Its buffers are sized by the machine, once at its start:
      small   less than 2 MB of free fast RAM (the stock A1200):
              8 TCP connections, a window of 1,932 bytes, a 4 KB send
              buffer a connection, 24 KB of buffers in all
      large   2 MB of free fast RAM or more: 32 connections, 16 KB
              windows and send buffers, 200 KB of buffers in all
    The kernel log says which (dmesg: "netd: serving net, epoch N, small
    profile (24 KB of buffers)"). The users other than root together get
    all TCP connections but 2 and all UDP sockets but 4 (6 and 4 on the
    small profile): root's servers always find one.

    The files are never read for a request other than ifup's (a floppy
    read would stall the network).

    Network cards are run by drivers: small programs in /sbin/net that
    netd starts for a stanza of /etc/network/interfaces whose "driver"
    is not slip (/sbin/net/NAME IFACE ARGS), as its own children. A
    driver claims its card, borrows netd's buffers and moves frames in
    batches; netd rings it (a byte on a pipe) when it has work. When a
    driver ends, netd logs it ("net: eth0: /sbin/net/a2065 (pid N)
    ended, status S"), takes the interface down and starts the driver
    again (after 0, 0, 1, 2, 4 seconds); the fifth end within a minute
    gives the driver up until ifup. The kernel stops the card (the
    driver's quiesce program) whenever a driver or netd ends, before
    any of their memory is freed ("drv: claim of ... released" in the
    log). An "inet dhcp" stanza asks a DHCP server for its address,
    netmask, gateway and name servers; DHCP's name servers are used
    only when /etc/resolv.conf names none.

    When netd ends (a crash, a kill), every socket of it fails at once
    with "network is down" (ENETDOWN), and a program waiting on one
    wakes up; the next socket call starts a new netd. Connections are
    lost, as when a router restarts. Five ends within a minute and the
    service manager gives up (svc: net: given up): socket calls then
    fail with ENETDOWN until root registers it again.

FILES
    /sbin/netd               the server
    /etc/hosts               addresses and names: "127.0.0.1 localhost",
                             an address and its names a line
    /etc/resolv.conf         name servers: "nameserver 10.0.2.3" lines
    /etc/network/interfaces  the interfaces (ifconfig(8))
    /sbin/net/NAME           the drivers (a2065(4), genet(4), ne2000(4),
                             plipbox(4))
    /usr/share/licenses/lwIP lwIP's licence

NOTES
    No IPv6, no firewall, no raw IP sockets (SOCK_RAW: "protocol not
    supported"); ICMP sockets send echo requests only. netd runs at
    nice 0 (not -10 as the disk servers): a flood from the network
    cannot starve the shells. Its log lines go to the kernel log, and
    so do its drivers'. Drivers are polled (no interrupts yet); no ARP
    probe of a DHCP address.
