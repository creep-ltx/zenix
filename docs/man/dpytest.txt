DPYTEST(1)		Zenix manual

NAME
    dpytest - test the display server

SYNOPSIS
    dpytest [-fb WxHxB] [-f FILE]

DESCRIPTION
    A test client of displayd and libdisplay (DESIGN D38 steps 3-4), run
    by tools/dpy-test.sh. It starts the display server on its console and
    reads commands from its standard input, a line each, answering a line
    "dpytest: ..." for each:

        win NAME W H PEN [X Y]
                           a window W x H filled with PEN, its name in
                           it; X Y the place it asks for
        text NAME X Y S    text at X, Y
        utext NAME X Y S   the same in the desktop's font
        font               the desktop's font (DPY_FONT_INFO): its id,
                           height, baseline, width, flags, name and the
                           widths of A D W . and space
        hole NAME X Y W H  a rectangle of pen 0 inside, kept when drawn
                           again (the chips' drag test)
        pens NAME          a patch of all 16 pens in it, kept when drawn
                           again (the drag the chips cannot lift)
        wm                 become the window manager
        move NAME X Y      place the frame's top left (the manager's)
        size NAME W H      the inside's size (the manager's)
        raise, lower, focus, hide, show, close NAME
        scroll NAME N      the inside up N lines, the freed ones filled
        info NAME          its place, size and state
        bad NAME           a batch with a broken order (refused)
        time NAME N        N raises and N moves: the mean round trip
        mem                free RAM, the memory of displayd and dpytest
        mode [hires|lace]  the screen's mode (DPY_MODE; none: only asked):
                           "dpytest: mode M screen WxH"
        stat [LABEL]       the server's counters since the last stat
                           (DPY_STAT): blits, pixels, glyphs, draws,
                           paints, copies; a whole drag's moves, their
                           time (movet, E-clock ticks), shows, their
                           time (showt), the time waited for the beam
                           (waitt), shows late for it; then counted
                           from 0 again
        events             the events received so far, a line each
        peek X Y           (with -fb) the pretend card's pixel at X, Y,
                           its bytes in hex as they lie in memory
        mouse DX DY        the mouse moved DX, DY counts (CON_INPUT,
                           root's), no button
        quit               the end

    EV_EXPOSE is answered by drawing the window again.

    -fb WxHxB (root's; DESIGN D43, run by tools/rtg-test.sh): before it
    connects, a pretend graphics card of W x H pixels of B bytes (2:
    R5G6B5, 3: R8G8B8, 4: A8R8G8B8) is recorded in the boot's hardware
    table, as zenixboot RTG records a real one, so the display server it
    starts draws the desktop there. The server allocates the card in fast
    RAM itself (it lives as long as the server draws on it) and clears
    the record when it ends. Refused while a display server runs. With
    memory protection on (zenixboot MMU=ON) dpytest may not write the
    table and is ended.

NOTES
    The times are those of the machine it runs on; in an emulator they are
    the emulator's.
