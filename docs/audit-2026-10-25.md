Found while fixing: `sh` ran out of its 256 KB arena on `rootfs/tests/cmds.sh` (about 90 lines) when one
~330-character line was added: "sh: out of memory" before any output. **Fixed** (shmem branch, commit 41ee527, with 36eed18 for `ps`; owner
2026-10-25 "fix things when we find them"): the arena was a fixed region of an eighth of free memory (64-256 KB) per
shell and a script was read and parsed whole (and a here-document reserved the whole rest of the text). Now the arena
starts at 8 KB and grows in chunks while a command needs them, gives them back when the command is done (one spare
kept inside a command, none at the prompt or between a script's commands), and a script, `.` file or start-up file is
read and run a command at a time (architecture.md section 12). An idle shell's `ps` MEM is 100 KB (60 KB data, BSS and
stack, the 8 KB arena, libz's first 32 KB malloc chunk); before, about 290 KB (`ps` did not count memalloc regions
then: fixed too, MEM now includes them). Free memory, stock A1200 (2 MB chip, no fast RAM), 1 / 2 / 4 logged-in
consoles: 1040 / 747 / 279 KB before, 1186 / 1001 / 662 KB after; 2 MB chip + 4 MB fast (fast free): 3062 / 2629 / 1794
KB before, 3307 / 3122 / 2782 KB after. A session costs about 185 KB instead of 293 (chip only) or 417 (with fast RAM).
Tests: cmds-test runs the awk-wide group inline again (a 532-character line; `rootfs/tests/awkwide.sh` is gone) and a
643-line script made at run time with a 2006-character line, a multi-line function, here-documents (`<<`, `<<-`, quoted),
if/while/case over several lines, a continued line, a line ending in `|` and in `&&`, a quoted string over two lines

Found by the shell-memory work (2026-10-26; the owner's rule: problems found are fixed next):
- **The prompt gave a syntax error for a multi-line `if`, loop, `case`, function, `{` or `(`**: it asked for more (PS2)
  only while a quote or here-document was open, though scripts already read on until a command is complete.
  **Fixed**: the prompt asks the same lexer-and-parser question (`cmd_incomplete`), so it prints PS2 and reads on as
  bash does; a lone `fi` is still a syntax error at once; a line ending in a backslash now continues on the next (it
  ran as it was before; inside an open quote the old join hid the new line). Test: jobs-test types each kind over two or three lines through the serial port and
  checks the results and the 15 PS2 prompts (with the old shell 10 of its checks fail).
- **sh's BSS was about 35 KB, 20 KB of it 4 KB expansion buffers**, and an expanded here-document was cut at 4088
  characters without a word (limits.md said longer was an error). **Fixed** where the arena fits: the here-document's
  and an assignment's joined value were copied from a fixed buffer into the arena anyway, so they are now built there
  (no limit; the here-document's buffer doubles when a value does not fit): BSS 35358 -> 27166 bytes. The word being
  expanded (4 KB of characters, 4 KB of quote marks, 4 KB for a case pattern's marks) stays fixed: the expander puts its
  results in the arena while a word is built, so a buffer there could not be released before the command ends and a
  command would strand one per word. Test: cmds-test expands an 8040-character here-document, compared with bash (the
  old shell printed 4088).
- **libz's first malloc chunk was 32 KB**: `login` holds one whole while it waits for its shell, `sh` one too, every
  server one. **Fixed**: the first chunk is 4 KB, each next one four times the last up to 512 KB (4, 16, 64, 256,
  512 KB; size classes, reuse and big blocks given back unchanged). Measured in FS-UAE on the 2 MB chip-only A1200
  (`ps` MEM, idle): login 54 -> 30 KB, sh 100 -> 72 KB (8 KB of it the BSS item above), fsd 159 -> 147 KB; `free`
  with consoles 1 and 2 logged in 1014 -> 1146 KB, and a second login costs 110 KB instead of 170. A 1 MB chip-only
  machine now has room for three sessions: the matrix logs in on console 4 too and checks that there the fourth is
  refused with init's message. Test: badptr (memtest) fills several growing chunks with 600 small blocks, checks
  their contents and their reuse after free.

Found while fixing: `tools/diag-test.sh` ran each cage-rig screenshot run under `timeout 60` (the stop builds, the
panic and 68000 runs; 120-130 s for the reset runs). The time included the wait for the machine's emulator lock, and
a timeout killed `shot.py` without ending its cage and FS-UAE (they run in their own session), so a run that waited
for another tree's emulator could leave FS-UAE running and every later emulator run (any tree) waiting for it.
**Fixed** (commit d47ca5c): `shot.py` ends its cage and FS-UAE on TERM, HUP and INT and on its own time limit
(`SHOT_LIMIT`, default the last screenshot or reset + 30 s, counted from the emulator's start, not the lock wait);
`fsuae_conf.load_cage` ends a half-started cage before letting go of the lock; `diag-test.sh` runs each part through
a `shot` helper that afterwards ends anything of the run still alive (its command line names the run's directory),
also when the script ends or is stopped (an EXIT trap); the outer timeout is now only a 30-minute last resort.

Found by the D15 design review (2026-10-26; open, fixed next after D14):
- **ext2 rename-over is not crash-safe** (kernel/ext2.c `ext2_rename`, about 1413-1440): it unlinks the target first,
  then adds the new name, then removes the old one, each a separate write-through block write. A power cut after the
  unlink loses the target (`/bin/sh` gone); after `dir_add`, two names share one inode with link count 1, and removing
  the leftover name later frees an inode still in use. Fix the Linux way: raise the moving inode's link count, rewrite
  the target entry's inode in place (one block write), remove the source entry, lower the count, then drop the old
  target inode. Test: kill the server after each block write, then `e2fsck -fn` (at worst a leaked inode). Check
  ZenixFS's rename too.
- **Structs the kernel writes into user memory must not grow**: D13 appended `shared` to `struct uproc`, so
  `SYS_procinfo` writes 44 bytes into an older `ps`'s 40-byte buffer (`UOKW` checks only the larger size). Fix: the
  caller passes its buffer size and gets at most that many bytes (for every such call: procinfo, stat/lstat/fstat,
  statfs, readdir, mountinfo, meminfo, disk info); write the rule (what is append-only or frozen) into CLAUDE.md.
