# Focused security audit of the network, 2026-10-28

Scope: roadmap block 2's checkpoint "a security audit" (ROADMAP block 2; D19 section 10 step 11, "a focused audit of
the network (security first), its findings fixed"): everything network-facing from D19 to D22 at `b36a33b`. That is
the kernel's socket layer (`kernel/sock.c`, `netproto.h`, `SYS_sock`/`SYS_netsrv`/`SYS_drv`, `kernel/drv.c`), netd
and the lwIP port, the drivers, SLIP and the `ttyS0` rings, random numbers, telnet and its console operations, Zmodem,
ssh with the crypto library, and D22's zpkg and HTTP cores. Four independent read-only reviewers each took one area
(kernel + netd + drivers; telnet + Zmodem + the console; ssh + crypto + keys; random + DHCP/DNS + zpkg/HTTP) and
looked for remote and local ways to corrupt memory, hang the machine, leak keys or get around a check. Every finding
below was checked again before it was fixed: reproduced with a test where possible, otherwise read from the source
(said so). Each fix comes with a test that fails on the old code. The NFS client (D23, `net/nfs/`) was built while
this audit ran and is not covered here: it was audited and fuzzed for 300 s when it was merged.

**Result:** 2 high, 6 medium, 14 low, all fixed; 9 left open with a proposal (a design question, or something that
needs the owner's hardware). The high ones: a second `listen()` with a bigger backlog let incoming connections write
past a heap block in netd (S1), and two loopback sockets that nobody reads made lwIP ACK its own ACKs for ever, so
netd never answered again and every program waiting on it could not even be killed (S22, found while testing S11).

Found while fixing:
- **F1 netd's objects did not depend on lwIP's headers** (Makefile `NETHDRS`): after S22's patch added a field to
  `struct tcp_pcb`, only `tcp_in.c` was rebuilt. netd then linked objects built with two layouts of the struct, and in
  FS-UAE it freed memory twice and stopped on an lwIP check (`sys_timeout`'s pool). **Fixed** (a separate commit,
  95b344a: `NETHDRS` names lwIP's include folders; after it, `make` rebuilt every lwIP object. Checked by the same
  bbs-test run, which passes; a build with stale objects is not set up as a test).

Left open, each with a proposal:
- **O1 a snapshot list is not bound to its name** (low; D22, `index.c` `ZP_T_SNAPSHOT`, mkrepo.py). **Designed (D22
  amendment 1) and fixed in the PC tools and the list core** (branch o1: a signed `snapshot NAME` line, mkrepo
  re-signs, zpkg refuses another name or a snapshot's list for a channel; test: zpkg-test net "--snapshot: an older
  signed channel list swapped in is refused (O1)"; zpkg itself on the Amiga still to be built against it). `--snapshot NAME`
  skips the serial and expiry checks, and nothing signed names the snapshot: someone in the middle of the plain-HTTP
  testing mirror can answer with any older list signed by the same key class. Shown by the reviewer (an expired list
  taken as a snapshot, rc 0). This is a change to the signed list format, so it goes in D22's note first, not into
  code: a signed `snapshot NAME` header line written by mkrepo and required to equal the name asked for, and a floor
  on its serial. zpkg on the Amiga is not built yet.
- **O2 ssh cuts keyboard-interactive text without saying so** (info; `auth.c` `info_request`, `auth_methods`): a
  prompt past the 2 KB text space shows empty; the methods list is cut at 159 bytes. CLAUDE.md's rule "a limit that is
  hit says so" applies. Fix with a note line ("the server's text was longer than ssh shows: cut") when an
  authentication test harness exists to check it.
- **O3 the DNS table is shared** (suspected; `DNS_TABLE_SIZE` 8): one user's 8 lookups of names that do not exist make
  other users' lookups fail with -ENOBUFS for a few seconds. The same kind of issue as S3; a per-user share as in S3
  when measured.
- **O4 the RNG200 is trusted after one check** (owner's hardware; `random.c` `rng200_take`): 32 bits a word are credited
  after only a repeated-word test, with no warm-up and no status bits. That is fine if Emu68 maps the block as the Pi
  does; to confirm on the PiStorm: read the status and the warm-up count as Linux's iproc-rng200 driver does, and
  discard the first words.
- **O5 HTTP chunk lines** (D22 step 5): chunk-size and extension lines are not counted against a total. A hostile
  mirror can send 4 KB of extension per data byte, up to the body limit. The per-file timeout planned for step 5 must
  be there before HTTP fetches packages.
- **O6 bundles are not yet verified on the Amiga** (D21 6.4, status): zenixboot has no `zc_sig_verify` yet, and zup
  checks each part only against the bundle's own table. Nothing fetches bundles over the network today; this must
  close before zpkg's slot write ships.
- **O7 the multiplier's timing on a real 68020** (D21 9.2, owner's hardware): the measurement on the stock A1200 that
  D21 plans is still to be made. FS-UAE and Emu68 cannot tell (Emu68 turns `mulu.l` into an ARM multiply).
- **O9 a process waiting on a hung netd cannot be killed** (design; S22 showed it): `net_call` waits for netd's
  reply in `ipc_kcall`, and a kill does not end that wait. D11 restarts a server that ends, but not one that loops.
  Proposal (with D23's killable wait for a dead NAS, the same mechanism): a kill cancels a socket call still waiting
  for netd's reply, and a watchdog notices a netd that answers nothing for many seconds and restarts it (the epoch
  rules already cover a restart).
- **O8 Zmodem has no cap on files per session** (judged acceptable): a board can offer thousands of honest small
  files; the disk filling up ends it, as with any download the user lets run. A cap would be a new option (the
  feature halt).

Dropped as unproven or not a finding:
- A DMA restart by genet after netd's end, into freed memory: it needs a ring stuck for a second just then; S2 now
  keeps the region until the driver itself is gone anyway.
- A driver lying about its DMA region in `DRV_ATTACH`: drivers are root's programs, and memory is not protected anyway.
- A directed broadcast through a second interface without SO_BROADCAST: not tested, minor.
- A board switching fonts back and forth (CPU and heap churn on the stock A1200): not measured; the keys are still read.
- Endless Zmodem headers: a hang the user ends with Ctrl-X five times.
- A `NAME.part` symlink planted by a local user, `lstat`/`open` races: local only, and without an MMU a local program
  can do worse.
- `ssh-keygen` not wiping the seed: Monocypher's `crypto_ed25519_key_pair` wipes it (read).
- known_hosts edge cases (a name over 296 characters, a file over 1 MB, a host known only by RSA/ECDSA keys): not
  remote, or OpenSSH's own behaviour.
- "The 68020's multiplier cannot be measured on the available hardware": the stock A1200 is one of the test machines
  (CLAUDE.md), so D21's plan stands (O7).
- A cross-linked (damaged) FFS data block under the slot file: the known risk of D22's design choice (e).

**What a machine without an MMU cannot promise** (D19 9.2, D21 9.1, stated here once more; not fixed, because it
cannot be): any program on the machine can read and write any memory. That includes netd's buffers (other users'
connection data), the kernel's random pool and its ChaCha key, netd's ISN and port keys, ssh's private key and
session keys while ssh runs, a typed password, and the device registers. Mode 600 on keys and the seed file only
keeps them from honest programs. A remote bug in netd's or ssh's parsing has the whole machine's rights (no
non-executable memory). So the promises are about the network: the kernel's checks on every socket call, root-only
ports, configuration and drivers, an authenticated and encrypted ssh session, signed packages, and fuzzed parsers. The
local promise is only "honest programs cannot do this by accident". Never run a program you do not trust while
logged in to something that matters.

Checked and found sound (the reviewers' summary): the kernel copies each socket request once and checks every pointer
by its direction, with the clamps, and every count netd returns is clamped again; `NETSRV_REPLY` finds the message
among the requests in flight; the privileges hold (`SYS_netsrv` is netd's, `SYS_drv` its children's, port `net` and
`/dev/ttyS0` root's, ports below 1024 root's, and SO_REUSEADDR never shares a port between users); the epoch rules hold;
received frame lengths are bounded twice, short frames are padded with zeros, and DMA regions are cleared; SLIP frames
are checked before lwIP; the telnet core and the Zmodem engine survived 2.5 M and 1 M fuzzed inputs, and kernel/term.c
600 k random writes under ASan; ssh checks the tag before the length is used, enforces strict kex, reset sequence
numbers and a fixed host key across rekeys, and cleans every server text; X25519's all-zero result is refused; http.c,
index.c and ffsslot.c check their bounds and overflows; the list's signature is checked before any line is parsed.
